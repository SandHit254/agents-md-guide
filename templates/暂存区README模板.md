> **目的**：让"什么东西该放哪"变成白纸黑字，避免几个月后变成 1000+ 文件无人敢清。
> 使用前删掉本引用块与所有 `<占位符>`。

# `<暂存区名>` 工作根目录

> **本文档是固化规约。新增文件前先看这里，别把东西随手丢在根目录。**

## 这个目录是干什么的

`<暂存区路径>` 是 **AI 编码助手的工作暂存区**。它**不是项目目录** ——
项目代码在 `<项目根>`，业务文档在 `<文档根>`，交付物在 `<各项目>/交付物/`。

**它存在的意义**：把「过程中的中间产物」和「正式成果」隔开，避免污染项目目录。

## 目录结构

```
<暂存区>/
├── README.md      ← 本文件（固化规约）
├── Temp/          ← 真临时：跑完即弃的脚本、日志、缓存。可随时清空
├── Tools/         ← 可复用工具：跨会话/跨项目还会用
├── Ref/           ← 参考资料：厂商文档、台账导出、上游源码参考
├── Archive/       ← 归档：会话归档、旧版本产物、被取代的源码副本
├── Docs/          ← 文档产出：诊断报告、方案草稿
└── NotWork/       ← 与工作无关的暂存，不删但也不混进上面几类
```

## 分类判定（放之前先问自己）

| 问题 | 是 → | 否 ↓ |
|---|---|---|
| **跑完这一次就没用了？** | `Temp/` | 继续问 |
| **下次、别的项目还会用这个脚本？** | `Tools/` | 继续问 |
| **是别人给的资料/上游源码？** | `Ref/` | 继续问 |
| **是旧版本/会话/被取代的东西？** | `Archive/` | 继续问 |
| **是产出的文档？** | `Docs/` | 继续问 |
| **跟工作无关？** | `NotWork/` | 别放这，回项目目录 |

**三条硬规矩**：

1. **根目录不放文件**。任何文件必须落在上面某一类里。
2. **交付物不放这**。包 / 镜像 / 二进制归各项目 `交付物/`（有台账登记）。
   这里只允许存在**临时副本**，用完即清。
3. **正式文档不放这**。项目文档在各项目 `记录/`；这里是草稿与中间态。

## 各类的清理规则

| 目录 | 可清理性 | 规则 |
|---|---|---|
| `Temp/` | **随时可清** | 无价值即删。`cache/`、`__pycache__/`、`*.log` 可定期清 |
| `Tools/` | **不要清** | 每个工具必须有说明；删前先确认没被引用 |
| `Ref/` | **不要清** | 重新获取成本高（厂商文档、导出台账） |
| `Archive/` | **谨慎** | 归档为了回溯；确认无回溯需求再清 |
| `Docs/` | **不要清** | 确认内容已并入项目文档后，才可清 |
| `NotWork/` | **不管** | 不属于工作范围，不主动清理 |

## Tools 的要求

`Tools/` 里的脚本必须能在**别的会话里独立跑起来**：

- **不依赖本目录之外的临时态**（别引用 `Temp/` 下的东西）
- **顶部写清**：用途 / 运行方式 / 依赖
- **登记到 `Tools/README.md`**：文件名 + 一句话用途 + 入口命令

## 历史上犯过的错（别再犯）

| 错误 | 后果 | 规矩 |
|---|---|---|
| 把**交付物**丢这当长期存储 | 与项目 `交付物/` 重复，产生 GB 级冗余 | 交付物只进项目仓库 |
| 把**无关文件**（视频、爬虫、素材）丢这 | 混进工作区，无法判断价值 | 进 `NotWork/`，或根本别放 |
| **会话归档**堆在临时区 | 容易误清，且与临时文件混淆 | 进 `Archive/sessions/` |
| 一次性脚本平铺根目录 | 上千个文件无法检索 | 进 `Temp/`，反复要用的才升 `Tools/` |
| **只看文件名判断归档内容** | 扩展名会撒谎 | **先看内容**（`tar -tzf` / `zipfile.namelist()`）再信名字 |
