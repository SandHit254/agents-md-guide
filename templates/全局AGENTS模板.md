## 全局工作纲领

核心是**软件工程思想**：把每件工作当工程做 —— 明确目标 → 拆解 → 设计 → 实现 → 验证 → 交付 → 复盘。

### 一、全流程（六阶段，每阶段有产出、有验收）

| 阶段 | 做什么 | 产出 | 验收 |
|------|--------|------|------|
| 1 需求分析 | 确认真实需求，列验收标准 | 需求说明 | 用户确认 |
| 2 概要设计 | 定架构/数据模型/选型，评估风险 | 设计说明 | 方案通过 |
| 3 编码实现 | 小步实现，写自测 | 代码 + 改动记录 | 功能正确 |
| 4 测试 | 单测→集成→系统→验收 | 测试报告 | 测试通过 |
| 5 部署交付 | 构建→部署→验证；**有回滚预案** | 部署记录 | 线上可用 |
| 6 后期维护 | 监控、修缺陷、沉淀经验 | 维护记录 | 问题闭环 |

### 二、编码细则

1. **先理清再编码** —— 不确定就提问；发现更简方案主动提
2. **简洁优先** —— 最少代码实现需求；不为一次性功能搭抽象层
3. **只改必要的** —— 绝不顺手重构正常代码；无效代码标注而非直删
4. **目标导向** —— 先定完成标准；改完循环自检

### 三、贯穿原则

1. **可恢复性** —— 未敲定的操作必须可回滚；改了什么/为何改/怎么还原有案可查
2. **记录留痕** —— 环境、配置、改动、坑全部记录
3. **验证驱动** —— 不跳过验证；出问题先复现再修
4. **边界意识** —— 不动系统底层/生产/他人代码前先确认
5. **知识闭环** —— 踩过的坑立即沉淀成规则

### 四、沟通与输出

1. **简要** —— 少说多做，去掉铺垫
2. **目的导向** —— 告诉用户"我在做什么、为什么、做完会怎样"
3. **教学式** —— 解释原理，让对方能判断和接手
4. **不吞错误** —— 出错如实说，带上下文

### 五、文档分层（单一事实源 + **索引而非内容**）

**`AGENTS.md` 是索引，不是百科全书。** 它只回答"去哪找"，不回答"是什么"。

| 层 | 体量红线 | 放什么 |
|----|---------|--------|
| 全局 AGENTS.md（本文件） | **< 15 KB** | 跨项目通用规则 |
| 项目 AGENTS.md | **< 30 KB** | 一句话结论 + 指针 |
| 详细文档 | 不限 | 完整过程与实证数据 |
| 记忆 | —— | 环境/凭据/决策 |

**判定**：单条信息超过 2 行 → 下沉到详细文档并留指针。
**膨胀症状**：单行超过 300 字 = 该拆了。
> 通式与模板见 `<规范仓库地址>`。

### 六、复盘闭环

- 每阶段/项目结束复盘：什么成功了、什么错了、下次怎么改
- 复盘结论回写到四层（全局规则 / 项目 AGENTS / 记忆 / 文档）
- 反复犯的错 → 沉淀成规则（失败 → 规则 → 不再犯）

## 暂存区落位规约

**根目录不放文件**，临时产物按性质落位：

| 目录 | 放什么 | 可清理性 |
|------|--------|---------|
| `Temp/` | 真临时：跑完即弃的脚本、日志、缓存 | **随时可清** |
| `Tools/` | 可复用工具（须登记 `Tools/README.md`） | 不要清 |
| `Ref/` | 参考资料：厂商文档、导出台账 | 不要清 |
| `Archive/` | 归档：会话归档、旧版本、被取代的源码 | 谨慎 |
| `Docs/` | 文档产出：诊断报告、方案草稿 | 并入正式文档后可清 |
| `NotWork/` | 与工作无关的暂存 | 不管 |

**三条硬规矩**：① 交付物只进各项目 `交付物/`；② 正式文档进各项目 `记录/`；③ 反复要用的脚本升到 `Tools/`。

## 工作方式

- 文件操作优先用专用工具；shell 仅用于构建、测试、git、进程等
- git 提交遵循 Conventional Commits（中文 subject，小步提交）
- 新建项目必须：git init + `.gitignore` + 中文 README + 推 GitHub
- 文档风格：中文、正式专业、无表情符号
- 涉及 `<敏感区域>` 之外的操作前先询问用户

## Hard Rules（违反即纠错）

- 密钥/token 不放代码、配置、日志明文（用 `${VAR}` 占位）
- **破坏性操作先向用户确认**（删数据、强推、覆盖历史）
- **非只读的外部/生产操作必须先列计划获批准**
- 不吞错误：错误向上传递并包装，消息含上下文
- 发现反复犯的错，沉淀一条规则进本文件或记忆
